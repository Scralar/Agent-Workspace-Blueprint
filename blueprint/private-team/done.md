# Done and don'ts

Up: [README.md](README.md)

## Definition of done

Verify command run for the touched area · which tests ran, or why none ([../reference/testing-harness.md](../reference/testing-harness.md)) · smallest correct diff (coding-practices) · source files within ~500/800 or split planned · one-home docs updated (MCP note if tooling or **scope** changed) · README and entry file re-checked when product facts moved · ADR written **as you go** if the bar was met, and named at wrap-up, or one sentence on why none ([../reference/adr-decision-bar.md](../reference/adr-decision-bar.md)) · changelog if notable · backlog updated · correction recorded if it was a durable lesson · upstreaming proposed if the way of working changed in a way that generalises ([../extras/README.md](../extras/README.md)) · memory in the homes [README.md](README.md) defines, not a notes file · notes left that another agent can use · UI gates if UI ([../extras/web-design.md](../extras/web-design.md)) · **committed the unit** (commit-as-you-go default unless ask-first recorded) · not pushed unless asked.

## Do not

Always-on runbooks · empty ceremony folders · auto-generated repo-dump `AGENTS.md` · ADRs for every bugfix · rewriting accepted history instead of amending/superseding · parking this-turn work only in TODO · copying plugin skills into the repo · assistant MCP for a system the workflow already owns · `docs/superpowers/` trees unless chosen · one person's preferences in shared tracked files.
