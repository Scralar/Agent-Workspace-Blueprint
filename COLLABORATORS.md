# Collaborators

Who can push to this repository, and how that list grows. GitHub handles only. No emails or private names.

## Write access

| GitHub | Role |
|--------|------|
| [@Scralar](https://github.com/Scralar) | Maintainer. Owns kit ADRs unless an ADR names someone else. |

A **collaborator** here means GitHub write (or maintain) access on [Scralar/Agent-Workspace-Blueprint](https://github.com/Scralar/Agent-Workspace-Blueprint). Opening a pull request does not require that. Most improvements should come in as PRs from forks.

## How to request write access

Open an issue titled "Collaborator access" and say what you want to maintain. The maintainer decides. There is no SLA. Until you are added to the table above, send pull requests.

When access is granted, add a row to the table in the same change that documents it.

## What write access is for

- Merge reviewed pull requests
- Push agreed kit fixes to `main`
- Triage issues

It is not a licence to put private notes in tracked files, skip Verify, or force-push `main`.

## Code owners

Pull request review routing lives in [`.github/CODEOWNERS`](.github/CODEOWNERS). That file lists the same GitHub handles as this table.
